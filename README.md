# Foldarium — co-folding pose-triage quiz + benchmark pipeline

A game and a benchmark: you're shown a protein **binding pocket** with the ligand removed, plus a handful
of **anonymised predicted poses** from co-folding models. You either **pick the pose that binds**, or decide
**none of them are right**. The point is to measure where human judgement beats a model's own confidence
head — especially on **novel** chemistry, where the automated pick has real headroom.

▶ **Play the live demo (novel-only): https://rafwiewiora.github.io/foldarium/**

## Two games
- **EASY** — only ensembles that contain a correct pose; just pick it. Value = the picks the confidence
  head fumbles.
- **HARD** — pick the correct pose *or* flag **"none of these"**. Value = catching the ensembles with no
  correct pose (the model can never say "none"). Hard sessions are drawn **class-balanced** so the score
  reflects skill, not the base rate (see `app.js` `HARD_MIX`).

## Two datasets
- **CAMEO 3D** — AlphaFold3 poses from the weekly *prospective* co-folding benchmark (last ~12 months).
- **Runs-n-Poses** — a *retrospective* multi-method benchmark; poses are pooled across 5 co-folding methods
  (AF3, Boltz-1/2, Chai-1, Protenix) and anonymised. Novelty comes from the published
  `sucos_shape_pocket_qcov` training-similarity metric.

## Product-deployment handoff

Deploy the **repository-root frontend** to Vercel and connect it to Supabase. Vercel serves the quiz;
Supabase is the durable control plane and published catalog. Foldarium separately owns a
provider-neutral prediction pipeline whose workers can run any configured co-folding method on GPU
infrastructure. External predictions, including future OpenFold Portal OF3 results, enter through import
adapters; Foldarium does not depend on or contain Portal code.

The current GitHub Pages demo still loads a preset collection from the four root `quiz_items*.json`
files. Database-backed item loading is the next integration step. The old `app/server.py` and SQLite
leaderboard are reference code only; do not deploy `app/`. See [`DEPLOYMENT.md`](DEPLOYMENT.md) for the
current behavior, weekly prediction lifecycle, ownership split, and data contract.

## Training-similarity viewer — `benchmark/`
A companion viewer that shows each benchmark system alongside its **most-similar pre-cutoff training
complex** (Foldseek-derived) and the pose/prediction overlaps, to see memorisation vs genuine
generalisation. **Live demo: https://rafwiewiora.github.io/foldarium/benchmark/demo/** — 32 systems
(drug-like, **≥15 heavy atoms**, each with a pre-cutoff training neighbour; the 4 without a homolog and the
11 small ligands are excluded, matching the quiz's filters). Finding the nearest complex needs a **local
Foldseek install** (`benchmark/prep/build_training_similarity.py`); see `benchmark/README.md`.
The multi-GB pose/crystal directories under `app/` are **not** committed — they are regenerated by the
prep scripts. The repo-root `data/` and `data_rnp_aligned/` directories are the small novel-only subsets
the live demo needs. Runs-n-Poses browser assets use the experimental complex as their canonical frame;
each pose has a receptor-derived transform and audit trail in `alignment.json`. The optional full export
also includes every transformed prediction complex and is intended for release/object storage rather
than Git.

## The pipeline in one screen — see `prep/README.md`
CAMEO funnel (`prep/cameo/funnel.py`), from 8,682 targets:
`drug-like ligand` → **≥15 heavy atoms** → `≥3 scored AF3 models` → correctness split
(oracle / all-wrong / game-able) → crystal-aligned → ≥2 pose clusters → **single-pocket (<8 Å spread)** →
quiz items, bucketed into **game-able / all-wrong / all-correct**. The quiz then applies strict RMSD
thresholds (correct <1.5 Å, wrong >3 Å) and the `HEAVY_MIN=15` floor at play time.
